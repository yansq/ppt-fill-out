# ADR-0014：凭据登录改用 6 位工号

- 状态：Accepted
- 日期：2026-09-23

## 背景

业务要求账号注册时记录 6 位工号，用户以工号和密码登录，收集人在分发页同时识别填报人的姓名和工号。当前系统不开放公开自助注册，账号由运维通过 `seed:auth` 预置。

## 决策

- `User.employeeNumber` 为必填且唯一的 `CHAR(6)`，应用边界只接受六位数字，并保留前导零。
- Auth.js Credentials 只用 `employeeNumber + password` 查找账号；密码哈希、失败锁定、JWT 会话和实时授权策略不变。
- `username` 继续作为唯一的人员名称，`name` 可作显示名；分发列表优先显示 `name`，否则显示 `username`，并始终附带工号。人员可按姓名、用户名或工号搜索。
- `seed:auth` 要求同时提供 `AUTH_SEED_EMPLOYEE_NUMBER`、`AUTH_SEED_USERNAME`、密码和角色；重复工号表示更新同一账号。
- 既有账号按 `createdAt, id` 的稳定顺序回填 `000001` 起的工号，不改变用户 ID、角色及业务关联。上线前应由运维根据企业真实工号校正这些迁移值。

## 结果

登录标识与人员姓名分离，分发时可以使用工号消除同名歧义。这修订 ADR-0007 的 username 登录决定，不改变“无公开注册”和服务端资源授权边界。
