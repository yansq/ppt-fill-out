# ADR-0009：测试指标库与 P4 快照边界

- 日期：2026-09-21
- 状态：接受

## 背景

当前没有企业指标库的表结构和账号。为验证 P4 主链路，需要可重复初始化的测试数据，同时保持平台系统库与指标业务库分离。

## 决策

1. 示例指标数据存放在独立 MySQL schema `report_metrics_demo`。`metric_record` 以 `(data_source_code, metric_code, period)` 唯一，包含数据源编码、指标编码/名称、值/值类型/单位、`YYYY-MM` 年月、更新时间、更新人、版本与创建时间。`metric_record_change` 在同库记录修改前后值、原因及操作者。
2. 初始化脚本仅创建缺失表并插入缺失的样例行，不删除或覆盖既有指标记录；系统库中的 `DataSource`/`MetricDefinition` 只登记示例源与受限的映射。
3. 示例 Adapter 只查询固定的 `metric_record` 表，值条件参数化，不接收客户端 SQL、表名或列名。未来接真实企业库时以独立受控映射扩展，而非把任意 SQL 开放到 API。
4. 绑定时将指标实际年月、值、来源版本、更新时间/人写入 `PlaceholderBinding.sourceSnapshotJson`。切换查看年月只影响查询和选择，不改变 ReportTask.reportPeriod。提交事务从绑定快照生成不可变 `SubmittedValue`，外部指标的后续变更不追改提交。
5. 指标修改以外部库版本条件更新和同库变更历史为权威；系统库缓存/审计是派生记录。跨库没有分布式事务，若外部更新成功但系统镜像失败，应显式报告待同步，不能伪装成整体成功。

## 后果

- 示例库适合开发验收，不应当被当作真实企业指标库直接上线。
- Fast Preview 基于现有模板页 PNG 遮盖占位符区域再叠加 DOM 文本，是编辑辅助；P6 的真实渲染仍是最终版式依据。
