# ADR-0019：按需建立员工账号并开放填报人注册

- 状态：Accepted
- 日期：2026-09-24

## 背景

收集人分配任务时，部分填报人尚未注册。员工均有唯一的六位数字工号，但不希望预先将全员名册导入系统。此前登录只允许预置账号，分配接口只接受已有用户 ID。

## 决策

- 开放无登录态的填报人注册，收集六位工号、姓名和至少六位的密码。注册流程只能创建或补全 `FILLER` 账号，不提供角色选择，也不能认领预置的 `COLLECTOR` 账号。
- 收集人可以在页面分配时输入六位工号。界面暂存这个工号；确认保存时，服务端在分配事务中查询工号。若尚无对应 `User`，创建 `name = null`、无 `UserCredential`、具备 `FILLER` 角色的账号，然后关联 `SlideAssignment` 和 `FillInstance`。不预导入未分配员工。
- 员工稍后用同一工号注册时，补全该 `User` 的姓名和密码凭据，保持 User ID 及既有任务关联不变。已注册、已停用或保留给收集人的工号不能通过公开注册覆盖。
- 注册成功后，客户端直接使用刚提交的工号和密码建立 Auth.js 会话并进入工作台；自动登录失败时保留已创建账号并提示用户前往登录页。
- 工号唯一约束与事务用于避免同工号产生两条账号；密码继续使用随机盐哈希。未注册用户在界面显示“未注册员工”和工号，不展示内部占位用户名。
- 本阶段依用户要求，不校验注册人对工号的实际归属。系统因此无法阻止知道他人工号的人先注册并查看分配给该工号的任务；部署时需要评估是否增加企业身份认证或工号归属验证。

## 结果

收集人可在员工未注册时完成分配，员工注册后直接获得既有填报任务；数据库只按实际分配和注册需求新增人员。此决策更新 ADR-0014 中“不开放公开注册”的限制。
