# ADR-0023：外部指标自动发现

- 日期：2026-09-29
- 状态：接受

## 背景

现有指标目录与填报查询先读取平台 `MetricDefinition`，再按已登记编码查询示例源库。源库 `metric_record` 出现新编码后，页面无法看到该指标，也无法在月份日历中选择只包含新指标的月份。

## 决策

1. 指标目录、可用月份和填报指标查询在读取定义前，通过受控 MySQL Adapter 从固定 `metric_record` 表发现 `(data_source_code, metric_code)` 及其最近插入行的名称、类型、单位。仅在平台中创建缺失的 `MetricDefinition`，保留已有定义和绑定；并发发现使用唯一约束与 `skipDuplicates` 保证幂等。
2. 自动登记的定义沿用固定表映射，默认不可写。指标值仍从源库按月份实时读取，不把发现操作当作值同步；平台 `MetricValue` 镜像与历史仍按既有对账流程处理。
3. 同一平台数据源下若不同 `data_source_code` 使用相同 `metric_code`，现有 `(dataSourceId, code)` 唯一键无法表示两者，查询明确返回冲突，避免将值绑定到错误来源。
4. 指标管理页可见时每 15 秒重新读取目录与可用月份；用户切换月份或刷新页面也会重新读取。其他页面在各自发起指标查询时发现新定义。

## 后果

- 自动发现适用于当前固定 `metric_record` 示例协议；接入其他企业表结构仍须实现对应 Adapter 与受控映射。
- 指标源不可用时发现失败并返回服务错误；页面不会把旧数据误报为最新结果。
- 当前没有源库变更推送，已打开的指标管理页最长约 15 秒显示新指标；后台标签页恢复可见后在下次轮询更新。
