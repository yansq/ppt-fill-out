# ADR-0003：P3 采用 Auth.js Credentials 与实时数据库授权

- 状态：Accepted
- 日期：2026-09-21
- 修订：邮箱登录与账号标识由 ADR-0007 改为用户名；密码哈希、锁定、会话和授权决策保持不变。

## 背景

P3 需要真实登录和 Collector/Filler 资源授权，但项目尚未指定企业 OAuth/OIDC 身份源。P2 的临时开发身份不能进入任务分发阶段。现有 `User`、`Role`、`UserRole` 模型可承载业务身份与角色。

## 决策

首版使用 Auth.js Credentials 邮箱/密码登录，禁用公开注册。运维通过 `seed:auth` 创建角色并显式配置账号。密码以随机盐的 scrypt 哈希保存在单独的 `UserCredential` 表，不写入 `User`、日志或 API 响应。连续五次失败锁定 15 分钟；管理员重新预置密码时解除锁定。

会话使用 8 小时 JWT，但它只证明用户 ID。每次业务请求必须重新查询用户状态、角色和资源关系；不可把 JWT 中的角色或 UI 隐藏作为授权依据。模板上传需 Collector，模板读取需创建者或关联任务成员，重试需创建者。P2 临时身份配置及自动创建用户逻辑删除。

## 结果与边界

无需等待外部 OAuth 配置即可完成可运行的 P3 身份基线。`Account`/`Session` 预留模型此时不参与 Credentials JWT 会话。后续接入企业 OIDC 时应保留业务 `User` ID 和服务端资源授权层，并补充登录审计、账户恢复和更强的分布式限流。当前没有租户实体，不虚构多租户隔离；如产品确定多租户需求，需单独设计迁移与权限策略。
