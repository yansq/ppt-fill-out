# ADR-0012：草稿预览使用 PPT 原生文本位置

- 日期：2026-09-22
- 状态：接受

## 背景

P4 的静态背景 + DOM 动态层把占位符所在文本框的 anchor 当成字符位置。一个文本框可包含多个段落、混合 Run、多个占位符，并可能延伸到幻灯片边界之外。用户模板的 `accuracy` 位于长文本框第 3 段，而该文本框的 x/y/宽高不足以推算该词的实际位置；因此 DOM 叠加值偏移。

## 决策

1. 填报实例的草稿预览由 Web 按实例权限读取已保存的绑定快照和不可变模板，向内部 PPT Service 传入当前页每个 `(key, occurrenceIndex)` 对应的文本值。未绑定占位符传空值。
2. PPT Service 在临时 PPTX 副本里，按解析时相同的 shape/table/段落顺序和跨 TextRun 字符映射替换 `{{key}}`；替换文字写入起始 Run，保留其字符样式与所在段落、文本框位置。验证传入的 occurrence 全部存在后经 LibreOffice/PDFBox 渲染单页 PNG。原模板、常规缩略图和 SubmittedValue 均不改动。
3. Web 的预览 URL 包含 FillInstance 版本；服务端确认版本一致后渲染，避免浏览器混用旧绑定。图片只返回有该实例权限的用户，设置 `private, no-store`。保存草稿后客户端使用新版本 URL 重新加载图片，不再按文本框几何坐标做 DOM 叠加。
4. 这是交互中的草稿预览，不替代 P6 的最终报告生成、FinalValue 真实预览与导出验收。

## 后果

- 每次草稿版本变化需一次 LibreOffice 转换，通常比 DOM 叠加慢；后续可在保持版本和权限语义的前提下增加服务端缓存。
- 预览结果仍受目标环境字体与 LibreOffice 版本影响。生产内网镜像需固定字体集并对照实际模板验收。
