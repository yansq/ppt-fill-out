# ADR-0004：核心平台在企业内网独立运行

- 状态：Accepted
- 日期：2026-09-21
- 修订：其中 TLS 作为入口前提的决定由 ADR-0006 修订；其余内网运行决策不变。

## 背景

最终部署环境位于企业内网，运行时可能无法访问公网。P3 的认证、任务分发、模板预览和状态查询不得依赖公共 OAuth、CDN、字体服务或外部 API。容器镜像与依赖可以在受控构建环境准备，但内网部署必须能够只使用内部镜像仓库或预加载镜像启动。

## 决策

- 核心拓扑仍为 Web、内部 PPT Service、系统 MySQL 和共享 Volume；浏览器只连接 Web。Credentials 身份源不需要公网；以后若采用 SSO，只接企业内网 OIDC/LDAP 网关，并保留服务端资源授权。
- Web 静态资源随 Next.js 构建产物打包，不引入远程字体、脚本或样式。模板、预览和填报数据只走本地服务、内网数据库与共享文件卷。
- Compose 默认将 Web 绑定到 `127.0.0.1:3000`，由可信内网反向代理提供 TLS 和访问控制；代理在其他主机时显式设置 `WEB_BIND_ADDRESS` 为受控内网地址。`AUTH_URL` 必须设为浏览器实际访问的内网 URL，代理应清理并重写 Forwarded/Host 头。
- 内网节点不执行在线依赖下载。镜像在受控 CI 构建并推送内部仓库，或以镜像归档导入；启动时使用已存在镜像。MySQL、LibreOffice 和 CJK 字体均由内部可用的镜像/软件包提供。
- Next.js 构建和运行镜像显式设置 `NEXT_TELEMETRY_DISABLED=1`，避免匿名遥测出站。
- P7 的 AI 为可选能力，必须配置企业批准的内网 OpenAI-compatible endpoint；核心 P0-P6 流程不因 AI 服务不可用而失败。

## 后续验证

P3 验证业务请求仅依赖内网服务。P7 交付前需做断公网启动与主流程演练、内网 HTTP/HTTPS 入口及代理访问控制检查、镜像离线导入和备份恢复演练；在这些验收前不声称“完整离线交付”。
